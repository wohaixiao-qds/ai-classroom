欢迎来到 Agent 入门第一课。今天只讲一个问题：harness 是什么。学完这节课，你要能回答一句话——agent 里，除了大模型以外的所有东西，都叫 harness。我们开始。

核心公式

一个公式，先背下来

agent=LLM+harness

LLM 是发动机，harness 是除发动机外的所有零部件。

移项一下：harness = agent − LLM —— 把大脑拿掉，剩下的都是它。

讲稿 · TTS 播放内容

记住这个公式：agent 等于 LLM 加 harness。用汽车做类比：LLM 是发动机，harness 是除发动机外的所有零部件——底盘、轮子、方向盘。注意措辞：是"除发动机外"，因为发动机本身也是零件。所以 harness 等于 agent 减 LLM，把大脑拿掉，剩下的都是 harness。你自己开发的部分，就是这块。

心智模型

汽车类比

发动机 = LLM

只会"读文字、吐文字"，没有手，不能自己干活。

其余零件 = harness

轮子、方向盘……让发动机的力真正落到地上的一切。

整辆车 = agent

零件相加才是整体——所以 harness 是 agent 的零件，不能反过来说。

看这张图。整辆车是 agent；橙色方块是发动机，也就是 LLM——它只会读文字吐文字，没有手；蓝色的是轮子，代表 harness 的各个部件，让发动机的力真正落地。这里有个常见的坑：等式装反，记成 harness 等于 agent 加 LLM。零件不能包含整体，方向别搞反。

关键区分

规则 ≠ 执行

规则 静态 · 菜单

纸上写着："当 agent 说 open，就打开文件"。它躺在配置里，本身什么都不干——就像菜单说应该怎样做菜。

执行 动态 · 厨师

真的有代码去打开文件、把内容塞回去。模型只会"说"，执行就是替它动手的那双手。

harness = 规则（菜单）+ 执行（厨师）——缺一样都动不起来

讲稿 · TTS 播放内容

很多人以为 harness 只是一套规则、一份规则手册。方向对，但漏了关键一半。规则是静态的，像菜单，只说"应该怎样"；执行是动态的，像厨师，真的动手做。模型只会输出文字，没有手，harness 的执行部分就是替它动手的那双手。规则加执行，合起来才是完整的 harness。

眼见为实

最小 harness 长这样

# 任何 agent 框架，本质都是这个循环的变体
while not done:
    resp  = llm(messages)        # 决策 → LLM        
    cmd   = parse(resp)          # 解析 → 你写       
    result = execute(cmd)        # 执行 → 你写       
    messages.append(result)      # 反馈 → 你写       
    done  = check(result)        # 终止 → 你写

五行里只有一行是 LLM，其余四行全是 harness。所以一个 agent 项目里，约 80% 的代码其实在写 harness。

讲稿 · TTS 播放内容

我们看代码。一个最小的 harness 就是这个 while 循环：LLM 负责决策，输出想干什么；你写的部分负责解析它说了什么、真的去执行、把结果塞回对话、并判断什么时候停。注意看：五行里只有一行是模型，其余四行都是你写的。这就是为什么说 agent 项目百分之八十的代码其实在写 harness。

往下一课预告

harness 内部：三层架构

层何时存在干什么
Scaffolding搭跑之前（编码期）提前摆好的静态材料：工具 / prompt / skills / 配置
Runtime跑跑的时候（运行期）让材料转起来的发动机：循环 / 解析 / 执行 / 上下文 / 终止
Eval验全流程拿一批任务反复测：真做对了吗？有没有退步？

⚠️ 三层不是三个 harness，是同一辆车的造 / 跑 / 验——一个东西的三个阶段。

讲稿 · TTS 播放内容

harness 里面还可以分三层：Scaffolding 是跑之前摆好的材料，Runtime 是跑起来让材料转动的发动机，Eval 是造完之后拿一批任务验证它行不行。用造车来记：造车、开车、年检——同一辆车的三个阶段，不是三辆车。这三层就是下一课的内容。
