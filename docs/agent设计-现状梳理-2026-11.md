# AI 课堂 Agent 设计 · 现状梳理（2026-11-20 更新）

> 本文记录**代码现状**，与 `docs/agent设计.md`（P2 施工图纸，代表设计意图）互补。
> 两者冲突时以代码为准，并以本文为快照。后续设计变更请在本文追加带日期的小节。

## 0 · 总架构原则（铁律 §1.2-7）

**一个 harness，多个循环**：基础设施只有一份（`app/core/` + `app/agent/tools.py` + trace），每个 agent 是其上装配了不同 prompt/工具/终止条件的**平级独立循环**。禁止「一个大循环调度所有 agent」（各 agent 节拍不同），禁止「每个 agent 自建配置/观测」（会碎裂）。

```
┌─ 共享底座 ─────────────────────────────────────────────┐
│ core/llm.py     客户端工厂+观测心跳(60s 交互护栏,240s 离线) │
│ core/prompts.py 输出规范集中(JSON规则/引用/批改标尺/四宝石)  │
│ core/trace.py   轨迹落盘(tutor/grade/research/prep jsonl) │
│ core/memory.py  答疑记忆(SQLite sessions/turns)           │
│ agent/tools.py  工具精选装配+emit_call 在飞提示+错误回收    │
└──────────────────────────────────────────────────────┘
        ↑点单                ↑点单               ↑点单
┌─ tutor ─┐        ┌─ research ─┐        ┌─ prep ─┐
│ 交互 SSE │        │ 批处理 分钟级│        │ 批处理   │
│ MAX_T=6 │        │ MAX_T=16   │        │ MAX_T=24│
└─────────┘        └────────────┘        └────────┘
        ↑调用                ↑输入材料
┌─ 单次 LLM 服务(不进循环) ──────────────────────────────┐
│ grader(批改) self_eval(自评) note_writer(蒸馏)          │
│ outline_attribution(归位)                              │
└──────────────────────────────────────────────────────┘
        全部被确定性编排层调用: pipeline.py / job_runner
```

## 1 · 共享底座

| 模块 | 职责 | 关键点 |
|---|---|---|
| `core/llm.py` | 客户端工厂 + 观测 | 智谱端点走 anthropic SDK；默认 60s 超时（交互护栏）；`messages.create` 包心跳观测（`⋯ 模型调用 #N`/`✓ 完成·耗时·tokens` 实时进任务日志）；`stream` 透传；`with_options` 派生放宽超时（prep/research 240s、蒸馏 600s） |
| `core/prompts.py` | **输出规范集中地**（方案 A，2026-11-17） | `JSON_OUTPUT_RULE`、答疑引用/窄框片段、`GRADE_OUTPUT_SPEC`（三行 comment+反背诵条款）、备课四宝石（PITFALL/DEV_LANDING/OFF_THE_SHELF）、`parse_json_reply()`（剥围栏→括号截取→对象校验） |
| `core/trace.py` | 执行与评估分阶段落盘 | 四类 JSONL 按 run_id 合并 started/progress/finished/assessment；失败/取消保留终态；记录版本与初始上下文快照 |
| `core/memory.py` | 答疑记忆 | SQLite sessions/turns；`load_messages` 取历史（含工具块），`append_turn` 落盘 |
| `agent/tools.py` | 工具精选装配 | 按用户/研究两套清单；`emit_call` 工具在飞提示；执行错误回收（工具炸不拖垮循环） |

## 2 · 三个循环 Agent

### 2.1 tutor —— 答疑（交互式，SSE，秒级）

| 维度 | 设计 |
|---|---|
| 触发 | 学员提问 POST /chat → SSE 流式 |
| 循环 | `MAX_TURNS=6`；每轮 `messages.stream` → **原始事件迭代**（`text_delta`→delta，`thinking_delta`→thinking 事件）；`stop_reason != "tool_use"` 终止 |
| 上下文组装 | system：教学规范 + 当前节±相邻节正文及全课目录 + 课程地图 + 已确认教训；当轮已掌握词、进度增量、当前节、检查点分块合并，不互相覆盖；引用门禁另读全课结构 |
| prompt 七规则 | 课件优先（注「课件第N页」）/ 课件外联网查（[1][2]）/ 学过的翻笔记 / 跨课融通 / 小步讲解 / 窄框排版 / 不瞎编 |
| max_tokens | 8192（5.3 思考+答案共吃预算） |
| 工具 | `read_notes`（vault 检索）、`web_search`——精选两件，无写权限 |
| 事件流 | `session → thinking* → tool_call* → delta* → done`；done 立即发，A6 自评挪 BackgroundTask |
| 终止与异常 | 软着陆：撞 MAX_TURNS 收工具只许作答（truncated 标记）；学员停止：AbortController → finally 落半截答案 |
| 记忆 | 历史进 SQLite 含工具块；**思考不落历史** |

### 2.2 research —— 找资料（批处理，分钟级）

| 维度 | 设计 |
|---|---|
| 触发 | 「我想学」一句话（request_research）/ 大纲点单缺缓存 |
| 阶段① 找大纲 | 零基础完整路线；权威地图 → 3~8 门课（goal/prereqs DAG/why 学习障碍或应用问题）；Agent 主题适用时保留模型弱点分析，不强套到其他领域 |
| 阶段② 找原料 | fetch_page 深读 8~20 要点、≥3 源；每点附逐字 quote。版本敏感主题查近期动向；稳定理论优先教材/一手资料，不强制近一年 |
| 工具 | `web_search`（博查/AnySearch/Tavily，recency）、`fetch_page` |
| 硬闸 | 大纲数量/id/goal/DAG/悬空；材料来源/要点数、唯一 source_id、实际抓取成功、quote 命中实际正文。错误页回工具错误；原文快照/摘录位置/指纹由 harness 构造 |
| 语义审查 | 原料逐点单次模型初审，supported/partial/unsupported/uncertain/unreviewed 独立记录；失败保持未审。摘录命中不等于语义支持 |
| 解析/终止 | `parse_json_reply`；校验通过=客观终止；MAX_TURNS=16 软着陆 |
| 缓存 | `{slug}.framework.json` / `{slug}.{子题}.material.json`；`--reuse` 零联网（整合课材料组装走此路） |
| 编排接入 | 样课先行（第一门入口课自动备）→ vault 快照同步 → 其余逐课点单 |

### 2.3 prep —— 备课（批处理，10~20 分钟）

| 维度 | 设计 |
|---|---|
| 触发 | 大纲点单 / 笔记备课 / pipeline |
| 循环 | `MAX_TURNS=24`；五件工具：`submit_plan` → `init_course` → `write_section`×N（重交同 id=替换）→ `validate_csl` → deliver |
| prompt | 教材作者立场（书面 prose 禁课堂腔）+ `_SHARED_STYLE`（块型菜单 7 种/文风红线/检查点纪律 + **四宝石**）+ `RESUME_PROMPT`（续写） |
| 四宝石 | 坑是主菜（每节必配 warn callout）/ 开发落地三问（每节收尾必答）/ 现成件（全课至少一处真实库清单）/ ——制度化自老 Claude 会话制出课的优点 |
| 规划闸 | 3~9 节 / 检查点配额 / covers 显式覆盖；保存原规划并在恢复与终验对照节 ID/顺序/测验。covers 是写作约定，不声称语义覆盖已验证 |
| 先修 | depends_on 即时校验（自依赖/悬空/缺 reason/超 2 门→打回）；大纲钦定先修覆盖模型建议 |
| 材料 | harness 将材料证据写入 meta.evidence，块通过 evidence_ids 关联；未知 ID 或引用被标为不支持的原料当场打回。历史材料保持待审 |
| 终止 | 终验通过=客观终止；软着陆兜底 |
| 观测 | op_log（append-only）+ `-u` 实时日志 + 前端 JobFeed |
| 取消/续写 | 执行尝试按 action ID 更新；稳定 binding 绑定材料快照/课件/规划指纹，按 ID 恢复，材料或规划变化拒绝混续；旧任务仅在来源唯一匹配时兼容恢复 |

## 3 · 单次 LLM 服务

| 服务 | 输入→输出 | 关键纪律 |
|---|---|---|
| grader | 复述+节内容+pass_rule → `{score, comment 三行✓✗→, precise}` | 3 次重试退避；score≥70 服务端判；tutored 保底 70；**反背诵**：纯背定义上限 60；零文本 RuntimeError 带诊断 |
| self_eval | 答案 + 课件窗口/会话/成功工具返回 → 支撑判定 | 高风险全审、其他稳定抽样；后台追加 assessment，失败/未抽中明确标未评；同源模型信号不作准确率 |
| note_writer | 三源蒸馏 → 笔记草稿 → 确认写回 vault | SSE 进度；apply 409 拒绝静默重蒸；32768/600s |
| outline_attribution | 未挂接课件 → 大纲行 | **一行一片**（已挂行不堆新片）；合并防覆盖；失败不影响交付 |
| evidence_review | 原料要点或实际课件块 + 原文摘录/上下文 → 支撑判定 | 无工具的单次模型审查；不沿用原料判定代替正文判定，人工标签另按内容哈希绑定 |

## 4 · 确定性编排层

- **`pipeline.py`**：①找大纲 → ②挑课（人审/auto）→ ③找原料 → ④vault 同步 → ⑤备课 → ⑥先修人审 → ⑦发布
- **`job_runner`**：三类后台任务（request_research 样课先行 / outline_prep 大纲点单 / request_prep 笔记备课）；共享收尾=校验→大纲挂接→发布→自动归位→状态落 SQLite；PID+SIGTERM 取消；`-u` 实时日志
- **人审闸两个**：挑课、depends_on 确认（auto 跳过）

## 5 · 设计不变式（改任何东西不能碰）

1. **客观终止优先于模型自觉**：校验闸 > MAX_TURNS > 软着陆
2. **行为、存在性、语义分别度量**：fetched/quote 命中不等于结论正确；pass_rule/goal/规划交付作机械验收，语义裁判与人工审查另记
3. **动脑活归人，机械活归程序**：人审闸、候选确认、默写不代填
4. **一个 harness 多循环**；编排是确定性代码不是 agent
5. **边界**：课件/学习数据不入 git；vault 只在明确指令下动

## 7 · 2026-11-20 审查收口

- 学习状态从观测窗口移至 `learning_grades`；测试来源不推进进度与复习。教训须 pending→人工确认后生效。
- 有据指标拆为工具行为、引用存在性、语义支持。高风险全审、其余稳定抽样；线上同源裁判尚未经足够人工标签校准。
- 任务状态区分执行退出和合格发布；绑定记录和规划终验支持可靠恢复，未交付产物不参与其他任务的全量发布。
- 新证据链在材料保存完整抓取正文，在课件保留摘录和邻近上下文；阅读器展示原文，`scripts/audit_evidence.py` 默认只读，模型审查需显式 `--model`。无人工标签不算最终语义通过。
- CSL 唯一结构源为 `schemas/csl.py`；静态 schema 使用现有 openapi-typescript 生成 `types/csl.gen.ts`，漂移检查串入 lint。HTTP 契约继续走 `api.gen.ts`。
- 大纲的 why 改为学习动机，模型弱点是领域内可用的分析方式；新领域知识库目录不再回落 Agent，旧主题绑定保留。

验证与限制按 `AGENTS.md` 最新条目记录；固定评测真实模型输出与人工标签仍待积累。上述机制不保证页面完整、来源权威或模型裁判判断正确。
