### 明确不抄（及理由）

- **多 agent 圆桌 + Director 编排图**（OpenMAIC）：多学生人格增加 token 与 TTS 复杂度，与「成品课件+讲解」定位冲突；可只取其单 agent 退化形态（零 LLM 纯代码路由）。
- **GeoGebra/Mermaid 白板渲染栈**（ChatTutor）：数 MB applet + 依赖，与 reveal.js 形态冲突；只抄协议思想不抄栈。
- **mastery.sqlite3 事务层**（CAS+lease+event sourcing，2200 行）：解决多会话并发写，单人单进程一个 JSON 足够。
- **Memory RunManager / audit/dedup/merge 全模式 / 7-surface×4-slot 矩阵**（DeepTutor）：单人同步等待 + 2-3 个 surface 足够。
- **Papermorph SVG 引擎**：与其自绘引擎范式冲突，不替换 reveal.js；只抄 beat/[[mark]]/ask 抽象。
- **流式 JSON 数组输出协议**（OpenMAIC）：为「动作+语音交错」设计，本项目课件动作生成期已定，引入 partial-json 解析器属负复杂度。
- **human-skill-tree 技能树本体**：依赖隐含在目录编号里，没有机器可推理的图——若做技能树需自研（Study-Mate 的 DAG 更适合当起点）。
- **playback/edit 双 chrome、PPTist 元素画布、PostgreSQL、多用户体系**：与单机单人定位全面冲突。

# 附：四路拆解详细报告

## 一、DeepTutor（记忆 / 掌握度 / 生成管线）

### 1.1 三层记忆（L1 traces → L2 facts → L3 synthesis）

纯文件 + markdown，无向量库。L1 是按 surface 按天落盘的 append-only JSONL + 从现有工件只读扫出的实体快照；L2 每 surface 一份 markdown 事实清单；L3 跨 surface 的 4 槽位（recent/profile/scope/preferences）。证据链靠 markdown 脚注：每条事实带 ULID 锚点 bullet，脚注指向 `surface:entity_id`。升级不是自动触发——用户在 Memory workbench 手动点，LLM 按 chunk 增量抽取，强制「每条事实必须引用本 chunk 内可见的证据 id」。

关键实现：
- 目录布局 `deeptutor/services/memory/paths.py:1-105`：`memory/trace/<surface>/<date>.jsonl`、`memory/L2/<surface>.md + .meta.json`、`memory/L3/{recent,profile,scope,preferences}.md`、`memory/snapshot/<surface>/`。
- L1 `trace.py:36-63`：`TraceEvent{id(ULID), ts, surface, kind, payload, session_id, turn_id}`，写入失败静默吞掉（「追踪绝不能打断业务面」），每 surface 一把 asyncio 锁。大量 L1 内容来自 snapshot adapters 反查现有工件（`snapshot/adapters.py`），配 `EntityStamp` 指纹 diff（`snapshot/entity.py:50-73`）。
- L2/L3 文档格式 `document.py:1-61`：`# 标题 / ## 小节 / - 事实 [^1] <!--m_xxx--> / --- / [^1]: chat:entityid`；每条一个 `m_`+26位ULID（时间有序）；parse/serialize 纯函数幂等（`document.py:105-232`）。
- 增量 diff `consolidator/meta.py`：`.meta.json` 存 `seen_entity_refs`/`seen_l2_entry_ids`，纯 id 集合差。
- Update 算法 `modes/update.py`：①id diff → ②chunk_with_boundary 按 budget 切块（L2 20 chunks/L3 10，重叠 0.10，段落边界）→ ③每块一次 LLM 调用返回 `{"facts":[{text≤240, section, refs}]}` → ④ref pool 校验：只许引用本 chunk 头部列出的 citeable refs，越界/缺引用丢弃并计数 → ⑤AddOp 追加+原子写+undo 快照。
- Prompt `update_l2.yaml`：角色 memory curator；每条 fact ≥1 ref、≤240 字符、动词开头；**禁绝对化措辞清单**（除非引用原文）；`{"facts": []}` 是合法正确答案。L3 额外强制 hedge 模板「Across N interactions, the user X」，L3 refs 是裸 surface 名（让用户有 L3→L2→L1 干净三级证据链）。
- `preferences.md` 从不自动 consolidate，只由 chat 的 `write_memory` 工具写，且幂等去重（长循环反复发同一条→短路返回 already saved，issue #647）。
- Memory Graph 纯前端 `web/lib/memory-graph.ts`：三层同心圆（L3 内/L2 中/L1 外），强边 L2→L1 实体、软边 L3→L2 surface 锚点。
- 读取 `recall.py`：`recent()` 只读 stamps 不读正文；命中预计算 `days_ago` 整数（模型对 ISO 时间戳算日期会错）。

### 1.2 掌握度路径与间隔复习

聚合根 + 纯函数决策引擎：`LearningProgress` 存 SQLite 一行 JSON，「下一步学什么」由无 I/O 无 LLM 的 `policy.py` 纯函数算——**门控即游标**。按知识类型分两轨：MEMORY/PROCEDURE 量化门槛（最近加权正确率≥0.9），CONCEPT/DESIGN 定性门（费曼式讲解 LLM 评判 bool）。

- 数据 `learning/models.py:81-96,736-801`：KnowledgePoint{type: MEMORY|CONCEPT|PROCEDURE|DESIGN, prerequisite_ids}、mastery_levels、qualitative_mastery、learning_evidence（可重放）、repetition_states、learner_mastery_overrides（学生自称已会，带 provenance）。
- **服务端持答案**：PendingQuestion 把 expected_answer 存服务端标 sensitive（不进学生可见 trace）；options 是 `{label, body}` 二元组（注释记录真实 bug：扁平 "A: xxx" 字符串曾被正则拆错数学选项，models.py:357-366）。
- 门控 `policy.py:33-52`；`compute_mastery`（`mastery.py:24-45`）：最近 5 次加权（0.5→1.0）+ 低置信封顶（1 次≤0.5、2 次≤0.8）。
- next_objective 优先级（`policy.py:281-388`）：①pending 问题先批 → ②到期复习先复习 → ③第一个未过门的（已过门跳过=天然 test-out）→ ④完成。返回 NextStep，action 只是建议。
- FSRS-lite `scheduler.py`：默认序列 MEMORY [0,1,3,7,14,30,60]天 / CONCEPT [3,7,14,30] / PROCEDURE [3,7,14] / DESIGN [14,28]；`retrievability=exp(-elapsed/stability)`；正确→stability 增（含 spacing_bonus），错误→衰减；**同 session 短间隔重复不重复放大 stability**（issue #1541）；forgetting_risk = 1-recall+逾期+错题+lapse；`replay()` 从证据流确定性重建。
- 复习策略模板绑定 path 时**快照** intervals，模板删除不影响已排程（`review_strategy.py:55-105`）。
- Anki 导出 `notes/anki_export.py`：Anki 文本导入格式；**guid 用稳定 card_id，重复导入是更新不是新建**；math/code 先 stash 再转 MathJax。

### 1.3 Living Books 生成管线

两阶段人审 + 逐页后台编译：Ideation 提案（人确认）→ SourceExplorer 多查询并行扫描，结果缓存 `exploration.json`（**后续所有阶段零重复 RAG**）→ SpineSynthesizer 章节树（人确认）→ 逐页编译：PagePlanner 按 ContentType 模板规划 typed blocks，每 block 一个无状态 generator 并行填充。

- 落盘 `book/storage.py`：`book_<id>/{manifest,spine,exploration,progress,inputs,log.md,pages/*.json}`，全原子写；log.md 每操作追加一行。
- typed blocks（`models.py:59-84`）19 种；`Block{type, status, params, payload, source_anchors}`——**params 保留生成输入，任意 block 可重生成**。
- 章节模板 `_TEMPLATES_V2`（`page_planner.py:75-150`）：theory→section:intro 1200w→figure→quiz→flash_cards→section:synthesis 800w 等；LLM 规划失败回退静态模板。

- Page Chat：`page_chat_sessions.json` 存 `{page_id: session_id}`；`build_book_context` 按 block type 各自 formatter 序列化成紧凑 context（每 type 字符上限）。

- 语义批改凭证模式 `learning/semantic_assessment.py:1-59`："Provider output is evidence, never a transaction"——confidence<0.8 一律 ungraded+needs_clarification。
- 工作简报 `capabilities/mastery/tools.py:723-770`：`mastery_status` 只展开当前目标+前 3 个到期复习+prerequisite 闭包，其余折叠为计数+提示「要全图再调工具」。

## 三、claudemy + Study-Mate（生成管线与编排）

### 3.1 claudemy 调研-成课工作流

- 子题地图先行：搜「这个主题通常怎么教」，写 12-18 个子题 id（T01-T18）；**子题 id 是全管线对账键**。禁凭记忆猜课纲。
- 多样性写在建清单 prompt 里：20-40 页、三类来源混合（实践者/一手权威/至少几篇反对主流——「分歧是学习者必须思考的地方」）、**每站≤3 页防单源主导**；存盘<20 页或任一子题<2 页回头补搜。
- N-of-M 共识：M=该子题下有≥1 条笔记的**去重页面数**（含 Also: 行，即「有机会发言的来源」），N=支持页数；按页不按笔记；M<3 标 thin evidence；**Disagree 是每个主题块必填字段**。地图末尾强制 `## The big splits` + `## Coverage gaps`。
- 主题定义「写成 instruction」："Anchor with a specific number, not a round one" 而非 "anchoring"；两个方向相反的想法是两个主题。
- reader×N 并行（每人批名+约 8 文件显式清单）→ 结构化笔记（一句观点+精确 url+短引文+Kind 枚举+Level+Bias 声明）→ merger×1 只做聚类不回读原文。
- 样课先行：Step 6 写完第 1 课（跑检查+渲染）发给用户**直接停**；反馈**回写进传给后续 writer 的 brief**。
- lesson card 固定节序（checker 校验）：命名观点/三行 idea/Impact/Who says it(N of M+反方)/Try it(2-15min)/Rule to keep/**Skip（跳过零成本）**/Go deeper。产品语气：「Offer, don't order」（禁 you must/should，checker 拒）。
- check_lessons.py 确定性闸：必需节/禁语正则/字数带 280-350（实测校准注释）/`same_page()` URL 归一（精确匹配曾误杀合法引用让 writer 白跑三轮）/**引用不在 raw/ 的页面=硬失败**（编造来源唯一死闸）/教案也查（首测手查抓出 3 个张冠李戴的故事）。

### 3.2 Study-Mate 路线图与编排

- `curriculum.yaml`：nodes+edges；**数组顺序即教学位次**，prerequisites 只准指前面，位次倒挂报错（报错文案即规范）；边必带 `reason`；Kahn 环检测；实验课必须有非空 prerequisites（「它验收的就是学到目前能做出什么」）。
- kind（概念/实操/实验）只决定产不产 lab 材料，深度由 objective 决定（≤34 字可观察，禁「了解/熟悉」）；`practice` 三选一是方向不是配额；验收通过时实验节点+全部 prerequisites 一起置已学完。
- 字段纪律：title≤16 字；problem「想不出真实的问题就留空，不编人物情节——为凑字段编出来的场景比空着更糟」；防模板化自查「全部标题连读，同一句式=在套模板」；绪论禁「学科定义+发展史+本课结构」。
- 跨科目记忆：两份 MEMORY.yaml（工作区级画像三节+积累 / 科目级积累）；**注入白名单代码强制**（memory.ts:8-49，注释：「这条边界不能靠提示词约定——三处消费路径各写一遍就会漂」）；写入=末尾追加一行不整份回写；「事实不问学生、自评必问」。
- 五角色交接：总控垄断用户通道，子 agent 全新上下文；派工 prompt 只写「规格绝对路径+输入值+三条边界」，不复述要求；产物走 `.stage/<角色>/deliver/` + handoff.json（role/status/outputs[path,kind,sha256]/checks[gaps]）；**搬运不转抄**（不读进上下文再写出）；「自然语言回复不能覆盖 manifest——说完成了但 manifest 缺失按未交接处理」「没跑的检查不许写 passed」；锚点对账（课件 `::: quiz 锚点：<文本>` 与题库同键，对不上响亮报错——按序号对照会静默错位）；缺题要有 `empty_reason:` 落盘。
- resource-scout：只读高可信来源；「够定主干就停」三条件；「给入口不给知识」；正文落盘 `<subject>/sources/`，「原址当链接、落盘文件当路径」；**禁对截断内容拼接转写**；抓取预算一站≤8页/≤6正文/≤1req/s/不空转；清单每条标 `· 服务 <节点id>`，校验器报覆盖缺口 + 条数≤节点数×2。
- 消费侧硬规则（learning-coach）：「先把本节点的来源原文读进来再落笔；盘上没有就退回找资料，不许凭摘要写」。
