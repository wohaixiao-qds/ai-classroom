# AI 老师在线课堂 · 全套设计方案 v1.0

> 日期：2026-08-20 ｜ 状态：待评审
> 定位：个人版（本地部署、自己开发自己用自己优化），架构上为将来上线运营留路。

---

## 一、产品愿景

**一句话**：先做一间只服务一个人的 AI 老师——找资料、备课、讲课、答疑全自动，学习成果沉淀回个人知识库；**演化路径**：知识库沉淀足够后，用这些已学过的资料开出对外 AI 课堂，教别人。

**使用场景（按优先级）**：

| 阶段 | 场景 | 流程 | 内容来源 |
|---|---|---|---|
| **现在（主线）** | 我学习新知识 | ①找资料 → ②备课 → ③讲课 → 我提问复述 | 联网调研 + 知识库 |
| **现在（日常）** | 我复习巩固 | 知识库笔记 → ②③，答疑可联网延伸 | 知识库 |
| **将来（演化）** | 教别人 | 已沉淀的笔记 → ②对外版课件 → ③④ | **仅知识库里学过、验证过的内容**，不现编 |

关键约束：对外课堂的内容**只用已学习、已沉淀的资料**——保证教出去的东西是自己消化过的；对外答疑也收敛为以课件+知识库为主。这个演化不需要改架构，只是②的备课模板多一个「对外版」（去个人化、内容更体系化），P5 再加多用户。

**核心体验**：左边课件区（幻灯片+动画+TTS 逐页讲解），右边对话区（随时提问、复述批改）。

## 二、四 Agent 架构

```
┌──────────────────────────────────────────────────┐
│                  AI 老师课堂（本地）                │
│                                                  │
│  ① 找资料 Agent      （学新课才触发,联网调研）        │
│      ↓ 结构化原料                                  │
│  ② 备课 Agent        （笔记/原料 → 课件）            │
│      ↓ 课件（HTML+讲稿+图+自测+动画编排）             │
│  ③ 讲课模块          （TTS 逐页播放,动画跟讲稿节奏）    │
│  ④ 答疑 Agent        （课件+知识库打底,自学时可联网延伸）│
│      ↓                                            │
│  学习轨迹/反馈 → 写回知识库 / 优化②的教学模板          │
└──────────────────────────────────────────────────┘
        知识库（Obsidian vault,单向只读源,课件写独立目录）
```

### 各角色职责

| # | 角色 | 触发时机 | 输入 | 输出 |
|---|---|---|---|---|
| ① | 找资料 Agent | 学知识库没有的新内容 | 一个学习主题 | 结构化原料（来源清单+要点+优质片段，标注新旧实践） |
| ② | 备课 Agent | 每次出课 | 笔记或原料 + **本节课场景**（我学新课／我复习／教别人） | 课件：页面+每页讲稿+类比图+自测题+动画编排。内置两套模板**按场景选其一**：自学/复习用「自学版」（含复述检查点页、填空页）；教别人用「对外版」（线性+自测，当前样例结构） |

**② 的核心生成规范：「讲到什么，亮什么」（音画同步四道闸）**

> 来源：P1 开发中用户实测抓到的缺陷——讲稿念「移项」但画面不显示推导出的第二等式。此规则为正式使用（P2/P3 备课 Agent 自动生成课件）时的质量底线。

1. **生成约束**：每写一句讲稿必须自问「这句话提到的概念/推导/对比，画面上有对应元素吗？」——讲移项就要有 derived 等式、讲零部件就要有图部件、讲代码就要逐行亮。没有对应元素：要么加元素，要么改讲稿，不许只有声音没有画面
2. **自检步骤**：课件生成后 Agent 跑一遍自检（每句讲稿 ↔ 触发的画面元素清单），漏配自动补齐后才交付
3. **校验器兜底**：机械可查的模式进 `validate_csl.py`——如「讲稿含『移项/推导』但 formula 页无 derived」「code/table 页有 note 但未登记 fragment」「元素有动画类但讲稿无对应句」
4. **人工审校**：语义层面的同步无法 100% 机器判定，课件上线前用户审校是最后一道闸（本产品固有环节，不视为负担）
| ③ | 讲课模块 | 每次上课 | 课件 | TTS 逐页讲解、动画与讲稿同步。**自学模式按小步节奏**：到复述检查点自动暂停，学员复述、批改通过后才继续（对齐 CLAUDE.md 教学风格）；复习/对外模式线性播放 |
| ④ | 答疑 Agent | 学员随时提问 | 课件全文+相关笔记；**自学模式可联网**（WebSearch/WebFetch/GitHub/官方文档） | 回答/换个讲法/批改复述。自学时按「新旧结合」原则：课件知识打底，延伸问题联网查最新实践；对外模式（P5）以课件+知识库为主、联网为辅，保证内容可控 |
| — | 反馈闭环 | 课后 | 哪页停留久、哪里提问多、复答错误率 | 优化②的教学模板（对应 Eval 层） |

**架构对应 harness 三层**（本产品即 harness 知识的实践项目）：
- Scaffolding：①② 的 prompt/模板/工具配置
- Runtime：③④ 的运行循环、上下文管理
- Eval：反馈闭环 + 课件质量评分

## 三、课件规范（已验证的模板）

样例：`samples/harness第一课.html`（已确认视觉+动画方向）

- **格式**：结构化 HTML 课件（备课时由 Agent 从 Markdown 中间格式生成）
- **结构**：封面(标题+公式+元信息) → 概念页(核心公式逐项弹出) → 类比页(SVG 部件按讲解顺序登场) → 区分页(双卡片对比) → 代码页(逐行浮现,与讲稿节奏对齐) → 总结表(行依次浮现) → 自测页(题目依次滑入)
- **两套模板，按场景选用**：**自学版**在通用结构上插入复述检查点页（讲完一个子题暂停，等复述+🎯批改）和填空页（`==____==` 高亮空位，学员亲手填），用于自己学新课/复习；**对外版**即当前样例的线性+自测结构，用于教别人。备课 Agent 按当节课场景二选一
- **每页必有**：讲稿（TTS 念的）、动画编排（跟着讲稿时序）、必要时自测题
- **设计 token**：石墨蓝底 `#0E1116`、琥珀强调 `#F5A524`（发动机）、辅助蓝 `#6CB6FF`、Noto Sans SC + JetBrains Mono；尊重 prefers-reduced-motion
- **模板沉淀**：视觉与动画规范写进②的 system prompt/模板文件，反馈闭环持续优化它

## 四、技术选型（已定稿）

**总体**：独立程序（非 Claude Code 驱动）——后端 Python + 前端 React，前后端松耦合，中间靠 CSL 课件文件对齐。

```
├─ 后端（Python · FastAPI）
│    ├─ 备课 Agent：读笔记 → 生成 CSL（Markdown 课件源）
│    ├─ 编译器：CSL → HTML 课件产物 + 讲稿音频（调 TTS）
│    ├─ 答疑 Agent：接收前端当前页上下文，回答/批改
│    └─ 学习轨迹：写回 ai-classroom/ 目录
├─ 前端（React + TypeScript）
│    └─ 播放器：课件渲染 + 音频/动画同步 + 暂停续播 + 对话区
└─ 中间层：CSL 课件格式（自定义 Markdown schema，Python 写、前端读编译产物）
```

| 决策点 | 选型 | 理由 |
|---|---|---|
| 运行时主体 | **独立程序**（不用 Claude Code 当运行时） | 产品不绑定任何 Agent 工具；亲手写 Agent 循环 = harness 实践；上线路径直 |
| 后端 | **Python · FastAPI** | AI 生态最厚（LLM/TTS 库）；原生异步适合「等模型吐字」；自动 API 文档 |
| 前端 | **React + TypeScript** | 用户学习方向选择；生态大，AI 类前端开源项目多可参考 |
| LLM | **智谱 Coding Plan**（GLM，Anthropic 兼容接口）起步 | 包月零增量成本；接口兼容 → 切 Claude/混用只需改环境变量。注意其并发限制，将来多学员答疑需换 |
| TTS | **Edge-TTS**（免费）起步 | 零成本先跑；TTS 是可替换件，讲稿文本才是资产。音质不满意 → 火山/阿里付费或本地开源（后者为 Python，可单独做微服务，不影响主栈） |
| 课件格式 | **CSL**（Courseware Markup Language，自定义 Markdown schema） | 备课 Agent 输出稳定可校验；改课改 MD 即改产物；一份源出多产物（HTML/讲义/答疑知识）；可 diff 可版本管理 |
| 数据 | 知识库只读；课件/轨迹存 `ai-classroom/` 独立目录 | 隔离，不污染 vault |

**前后端耦合面**：仅两个——① 前端向后端要课件编译产物（静态文件）；② 播放状态/答疑走 FastAPI 接口。CSL 层使两边类型各自定义、互不 import。

**上服务器预留**（将来运营版）：课件产物是纯静态可 CDN；答疑 API 化即可多用户；加账号/配额/支付即可商业化。

## 五、分阶段计划

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| **P1 最小课堂** | FastAPI 骨架 + React 播放器（渲染第一课、TTS 音频播放、暂停续播、复述检查点）+ 答疑接口（智谱） | 用第一课**完整学一遍并完成复述对齐**——不是听完，是学进去 |
| **P2 备课管线** | 一条命令：指定笔记 + 场景 → 备课 Agent 生成 CSL → 编译成课件 → 本地打开即学 | 新笔记 30 分钟内变课件 |
| **P3 找资料+入库** | 学新主题 → ①调研 → ②③上课 → 学习轨迹自动写成符合 vault 约定的新笔记 | 用它学完一个新主题，笔记直接可用。**边界**：会话事实（讲了什么/纠偏了什么）自动写，默写巩固与填空区**留空等用户亲手填**（动脑活不许代填） |
| **P4 体验打磨** | 动画讲稿精确同步、复述批改界面、复习提醒（读 frontmatter 复习日期）、课件反馈统计 | 连续一周日常使用 |
| **P5 运营版预留** | 多用户、账号、部署上云 | 视届时需求决定是否做 |

每阶段结束必须产出「能用的一节课」或「能跑的一条命令」，防止范围失控。

## 七、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 做了不用（最大风险） | 🔴 | 每阶段以「自己真实使用」为验收；连续两周不用就砍功能找原因 |
| 范围失控 | 🔴 | 严格按 P1→P5；每阶段必须交付可用物 |
| AI 讲课质量差 | 🟡 | 课件生成后人工审校再学；答疑注明信息来源（课件内 vs 联网查到），联网内容标来源链接 |
| 开发挤占学习 | 🟡 | 开发即 Agent 实战学习（双重收益），但设时间盒 |
| API 依赖 | 🟢 | LLM 可替换；课件纯文本格式不锁定厂商 |
| 知识库污染 | 🟢 | 单向只读 + 独立输出目录；P3 的自动写笔记需遵守 vault 约定并经确认 |
