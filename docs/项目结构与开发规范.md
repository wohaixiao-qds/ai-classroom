### 边界铁律
1. `apps/api` 与 `apps/web` **互不 import**，唯一连接是 HTTP(SSE) + `packages/api-types` 生成产物
2. **跨语言不手写共享类型**：单一事实源在后端——FastAPI 导出 OpenAPI → `openapi-typescript` 生成 TS 类型到 `packages/api-types`，前端只 import 生成产物（永不漂移）；纯常量枚举才允许小量手写
3. CSL 课件 JSON 的 schema 定义在 `apps/api/app/schemas/`（Pydantic），前端类型同样从生成产物拿
4. 前端 feature 之间只 import 对方的 `index.ts` 公共出口，禁止网状深引用

## 二、后端规范（Python · FastAPI）

- **结构**：起步用扁平 type-based（routes/services/schemas），域超过 ~5 个或单文件膨胀时迁 feature-based（fastapi-best-practices 的演化路线）。**不引入完整 DDD**
- **分层纪律**：router 薄（参数校验 + 调 service）；业务逻辑在 service；async 路由内禁止阻塞调用
- **包管理**：uv（依赖/锁文件/虚拟环境/`uv run` 一把抓）
- **Lint/类型**：ruff（lint+format，line-length=100，规则集 `E,F,I,B,UP`）+ mypy strict；配置全集中在 `pyproject.toml`

## 三、前端规范（React · Vite · TS）

- **结构**：bulletproof-react 骨架裁剪——`app/ + features/ + shared/`，省略 entities 层
- **TS**：`strict: true` + `noUncheckedIndexedAccess`
- **Lint**：ESLint v9 flat config（eslintrc 已废弃）+ Prettier
- **UI**：shadcn/ui + Tailwind v4 + Lucide，设计 token 落在 CSS variables（深色一等公民）

## 四、API 规范

- REST：资源复数 kebab-case（`/api/v1/classrooms/{id}/sessions`），动词仅用于动作型端点
- **错误格式**：统一 `{"code": "MACHINE_READABLE", "message": "人话", "detail": ...}`——全局唯一 exception handler + 自定义异常基类，禁止裸抛（RFC 9457 的简化版）
- **SSE**（答疑流式）：
  - 握手前完成全部校验（响应头发出后无法再返回错误码）
  - 事件统一信封 `{type, data, id}`；流内错误用 `event: error`
  - 每 15s 心跳注释防超时；重连带 Last-Event-ID
- FastAPI 路由必写 `operation_id` + `response_model` + tags，保证生成客户端质量

## 五、Git 规范

- **Conventional Commits**：`feat:/fix:/chore:/refactor:/docs:`（对 AI 辅助生成 commit 尤其有价值）
- 分支：**简化 GitHub Flow**——main 上小步提交，或当天合并的短命 feature 分支；不搞 GitFlow/发版仪式
- 每个任务（T1~T6）一组语义化提交

## 六、质量工具链（根级统一编排）

`.pre-commit-config.yaml` 一个文件同时管两侧：ruff、mypy（api）+ eslint、prettier（web），commit 时自动跑。不用 husky，框架统一。

## 七、文档规范

- `README.md`：精简——是什么、怎么跑、架构一图
- `CLAUDE.md`：给 AI 的项目上下文 + 给未来自己的约定（常用命令、风格、目录地图、禁区）
- `docs/adr/NNNN-标题.md`：Context/Decision/Consequences，编号递增只追加；**只在「半年后会忘了为什么」时写**（如「为什么 SSE 不用 WebSocket」），不为仪式而写
