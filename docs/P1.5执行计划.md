## 一、两条并行工作流

```
① 答疑 agent 打磨（A1~A6）—— agent 内功（五维：工具/prompt/循环/上下文·记忆/观测）
② AI 教室骨架（B1~B3）    —— 产品外壳（路由 + 课表 + 观测页）
```

分开的理由：①改 agent 内部，②新增页面。混做则两头都不透。

## 二、任务清单与顺序

**开工顺序**（先验收暴露真问题 → 先建观测（后续打磨靠它验证）→ 再补内功 → 外壳）：

```
A1 → A3 → B0 → B2 → A2 → A4 → A5 → B1 → A6
```

| 编号 | 任务 | 验收标准 | 依赖 |
|---|---|---|---|
| **A1** | **P1 总验收** | 完整学完第一课、3 个复述检查点全部真批改通过、答疑真提问成功 | — |
| **A3** | 观测数据层：trace 结构化 | trace 能回答「问了什么/查了什么/耗时/引用了哪页/检查点结果」 | A1 |
| **B0** | 路由基建（`react-router-dom`，用户已批准） | 三条路由可切：`/` 课表、`/c/:id` 课堂、`/eval` 观测 | — |
| **B2** | Eval 观测页 | 指标条 + 问答轨迹（可展开）+ 检查点通过率 + **「课件未覆盖的问题」视图** | A3, B0 |
| **A2** | 记忆持久化 | SQLite（标准库 `sqlite3`，后端持有）存对话；刷新不丢；追问带工具上下文 | A1 |
| **A4** | 引用可点 | 回答里「课件第N页」可点击跳转到该页 | A1, B0 |
| **A5** | 会话管理 | 能新开一轮干净对话；历史会话可切回 | A2 |
| **B1** | 课表页（四泳道，见 §四） | 四类状态正确显示；点击触发对应动作（上课/备课/调研/确认候选） | B0 |
| **A6** | 答案自评 | agent 自查是否瞎编/是否有据；结果进 trace | A3 |

**明确不做**：学员画像长期记忆（依赖 P3 数据，无数据即空中楼阁）、多用户/账号（P5）、语音提问。

## 四、课表 = 学习指挥台（四泳道）

**核心设计**：课表不是静态列表，是**知识库结构的投影 + 课件状态的叠加 + 衍生候选**，零手工维护。

| 泳道 | 状态 | 数据来源 | 点击动作 |
|---|---|---|---|
| 在学的 | ✅ 已出课 | `courses/*.csl.json` | 进课堂（带断点续播） |
| 能学的 | 📝 有笔记未出课 | vault 笔记 | 触发②备课 agent（P2 入口） |
| 想学的 | ⬜ 待探 | vault 的 `*待探.md` | 触发①找资料→②备课（P3 入口） |
| 刚冒出的 | 💡 衍生候选 | 学习过程采集（见 §五） | 确认 → 升级为待探 / 直接出课 |

### catalog 接口（`GET /api/v1/catalog`）
```
1. 扫 vault 目录（只读!）→ 主题树，按编号目录排序，读 frontmatter
2. 扫 courses/*.csl.json → 已出课清单
3. 用 CSL 的 meta.source_notes 关联两边   ← T1 已埋好的字段
4. 读衍生候选池 → 合并输出：主题 + 状态 + 进度
```

### 两条规则（已定）
- **规则一 · 哪些笔记算课**：排除法——排除 `00-` 开头（导览）、`_` 开头（模板/Inbox）、根目录管理文件（术语表/进度/下次继续/README/CLAUDE）
- **规则二 · 同目录内顺序**：读该层 `*待探.md` 里的排列顺序（那本身就是用户排的探索顺序），零额外维护

## 五、衍生机制（学习不照本宣科）

**问题**：原设计假设学习路径 = vault 固定树；但真实学习会延伸（CLAUDE.md：发现连线/边角/配套概念就顺势延伸）。「值得单独学」的念头此前无处承接，会蒸发。

**两个层次**：
- 层次一 · 当场衍生：上课时提问 → 答疑 agent 查/答。**已能做**
- 层次二 · 沉淀成新课：**此前缺失，本计划补上**

### 采集口（两个，第二个免费）
1. **手动标记**：上课/答疑时一键「这个值得单独学」→ 进候选池
2. **trace 自动挖掘（零额外操作）**：`traces/tutor.jsonl` 已记录每个问题；**触发过 `web_search` 的问题 = 课件答不了的问题 = 天然衍生候选**。观测页（B2）直接展示：「这 N 个问题课件未覆盖，要不要开新课？」
   - 这正是「自我学习闭环」：Eval 层数据流回 Scaffolding，流回的是「该学什么」
3. （不做）agent 主动建议——容易滥，先不做

### 边界（必须守）
候选池存**项目内**（`ai-classroom/`），**不写进 vault**：
- vault 只读（边界铁律 5）
- 「值得学吗/归到哪类」是动脑活，程序不代填

**流程**：系统提议 → 用户在课表确认 → 用户自己决定是否写进 vault 待探清单。程序只负责「别让念头蒸发」，不替用户决策。

### 完整闭环
```
上课/答疑 → 冒出新问题
   ↓（手动标记 or trace 自动挖掘）
衍生候选池（项目内）
   ↓ 用户在课表审：值得学吗？
确认 → ①找资料 → ②备课 → 上课
   ↓
学习轨迹 → 用户决定是否沉淀进 vault
```

## 六、技术决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 路由 | `react-router-dom`（用户批准） | 前端基础设施，非可选优化；手写 hash 路由长期糙 |
| 记忆存储 | **SQLite**（标准库，后端持有） | ①记忆归 harness 不归 UI（前端存=agent 没记忆）②喂得上反馈闭环（备课 agent 可读历史问答）③零依赖 |
| 记忆 vs trace | 两者并存，各归各层 | trace=Eval 层（只追加、观测）；记忆=Runtime 层（分组、检索、参与上下文）。混用则格式一改记忆就崩 |
| 预算上限 | 不加 | 包月计费边际成本 ¥0 + MAX_TURNS×max_tokens 已封顶。备课 agent 若切按量付费再评估 |
| 学员画像 | 不进本轮 | 依赖 P3 学习轨迹数据 |
