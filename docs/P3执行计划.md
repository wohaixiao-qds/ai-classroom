# P3 执行计划 · 学习沉淀写回知识库

> 前置:docs/设计方案-v1.md §五(P3 边界)、P2 全部完成(M1~M5)
> 验收总标准:**用它学完一个新主题,笔记直接可用**;会话事实自动写,巩固/填空区留空等用户亲手填
> 2026-08-24 设计对齐:方案一(新主题开新笔记)+方案二(老主题增补)场景分流,用户拍板

## 一、已定决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 写回什么 | **蒸馏笔记**(三源:课件骨架/答疑对话/检查点批改),不是课件本身 | 课件=教学产物留项目;笔记=知识资产归 vault |
| 场景分流 | vault 无同主题笔记 → **新建**;已有 → **末尾追加日期块** | 与用户真实学习路子同构:新主题开篇、老主题加深;追加块易审校,不污染原结构 |
| 巩固区 | **留空**(默写题/填空),动脑活不代填 | 帮整理 ≠ 替学 |
| 确认闸 | **草稿预览(路径+全文+待探勾选)→ 人确认 → 才落盘** | vault 只读铁律为 P3 唯一开口,永经人手 |
| 待探勾选 | 同闸一并预览:`- [ ] X` → `- [x] X → [[笔记名]] ✅` | 学过即勾,闭环 |
| 蒸馏方式 | 单次 LLM 调用(无再决策,不进循环,图纸判据) | 同 grader/self_eval 姿势 |

**明确不做**:原始轨迹归档(噪音)、原子卡片化(与 vault 风格不符)、静默直写(违铁律)。

## 二、任务清单

| # | 任务 | 验收标准 |
|---|---|---|
| **N1** | `services/note_writer.py` + CLI(`python -m app.note_writer <course_id> [--dry]`):三源收集→LLM 蒸馏→分流(新建/追加)→草稿预览→确认→落盘(含待探勾选) | parsing-layer --dry 出合格草稿;真确认后 vault 出笔记、待探勾选、无越权写 |
| **N2** | 课程详情页「沉淀为笔记」按钮 + 草稿预览/确认 UI | 网页完成全流程 |
| **N3** | **端到端验收**:新主题从「我想学」到笔记落盘全环 | 用一个新主题完整走通:输入→课→学→笔记直接可用;复习场景增补已有笔记 |

## 三、边界(施工必守)

- vault 写入**仅**经确认闸且仅限:新笔记文件 / 既有笔记末尾追加块 / 待探行勾选——不做任何其他修改
- 笔记路径遵守 vault 层级(topic → 真实目录,同 find_todo_area 映射);未知领域主题的落点在闸中明示由人确认
- source_notes 关联:新笔记生成后,课程详情「关联材料」应能看到它(P3 内完成一次手动关联验证)
