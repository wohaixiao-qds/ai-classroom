# 生成中心流程与可信依据开发计划

本任务经用户批准（2026-11-20），允许 Agent Team 实施。承接现有任务绑定、子进程执行器、证据链与发布门禁，不引入新框架或依赖，不写学习知识库。

## 产品契约

- 输入主题默认生成大纲与首门样课；后续逐课点单沿用现有入口。
- 每项任务展示真实节点：需求与范围、参考调研、大纲、材料、规划、写作、验收修订、发布。不适用的节点明确跳过，历史任务缺记录不得补造。
- 支持停止、继续、删除；已发布课程与学习记录不因删除任务被删除。
- 可信度不设总分。抓取、指纹、摘录定位、结构与交付由程序核验；模型语义审查标明模型及限制；未人工审查如实显示。
- 参考映射若由模型提出必须标明，不将目录映射比例宣称为领域完整度。

## 实施分工

1. 后端任务与恢复：持久化结构化事件、任务详情/停止/继续/删除接口，保留稳定绑定，阻止过期执行回写；隔离测试。
2. 可信依据报告：整合实际大纲来源和发布报告，确定性检查与模型意见分栏，缺失状态明确；隔离测试。
3. 前端生成中心：任务卡与节点详情、可信依据、停止/继续/删除交互；API 类型由 OpenAPI 生成。
4. 主 agent：节点埋点、接口对齐、集成、生成类型、检查与交付。

## 接口约定

- GET `/api/v1/jobs`：任务列表。
- GET `/api/v1/jobs/detail?kind=...&target=...`：任务详情、持久化事件与关联产物。
- POST `/api/v1/jobs/resume?kind=...&target=...`：恢复已有任务。
- DELETE `/api/v1/jobs?kind=...&target=...`：移除任务记录与专属未发布产物，运行中先安全停止。
- 保留 POST `/api/v1/jobs/cancel`、GET `/api/v1/jobs/log` 兼容旧入口。
- GET `/api/v1/jobs/trust?kind=...&target=...`：可核查依据与审查者信息，不返回可信度总分。
- 事件包含序号、执行尝试 id、节点、状态、说明、时间和可选进度；以已持久化事实为准。

## 验收

- 刷新可恢复节点；停止后不能继续发布；继续保留有效产物；删除后旧执行不得复活任务。
- 审查恢复只复用模型、规则与输入未变化的有效结果。
- 来源、摘录与检查报告可追溯，缺项与历史未记录不显示为通过。
- 伪引用、篡改、先修环、缺章节、审查失败等故障路径有测试。
- 后端 unittest、相关 Ruff、前端类型生成/lint/build 通过；界面用隔离数据验证，不触发真实模型或 vault 写入。

## 实施边界

自动来源身份认证与完整参考体系覆盖评估需要可核实的身份记录和目录原文；本轮仅展示已取得的事实，不能用模型声明补齐。未实现的检查明确显示待补充。

## 本轮实现与验收记录（2026-11-20）

- 任务控制：结构化事件落 SQLite；按执行尝试隔离回写；取消立即封锁写入、进程退出前显示“正在停止”；继续复用绑定材料与规划；删除保留墓碑并归档专属未发布产物，保留已发布课程与学习记录。
- 节点展示：调研、材料、规划、逐节写入、最终审查、修订与发布按实际动作记事件；不适用节点显示跳过；历史缺事件不从日志推断通过。
- 可核查依据：来源与摘录、内容指纹、程序核验、具名模型审查分开展示；不设总分、不将模型映射作为完整性认证；报告绑定内容，变化后失效。
- 审查恢复：每批审查后原子保存检查点；输入单项、上下文、模型或提示规则变化时重审对应内容；未完成检查点不能授权发布。
- 离线验证：后端全量 unittest 133 项通过，相关 Ruff 通过，11 个后端模块定向 mypy 通过；前端 CSL 类型一致性、lint 与生产构建通过（存量 lint 与构建体积警告另行保留）。页面以浏览器内模拟接口验证了继续、停止、删除确认、历史缺记录、失效报告、报告请求失败清理及 390px 窄屏无水平溢出，未见浏览器运行错误，不发起真实生成。

### 待后续验证与增强

- 本轮未运行真实模型长任务，不据此声称真实课程教学质量或完整端到端稳定性已验证。
- 来源发布主体身份尚未自动认证；大纲参考映射仍是模型建议，领域完整性与零基础适配不作已验证承诺。
- 当前没有人工审核记录或人工认证结论；模型语义审查可能误判，程序放行仅表示满足已实现规则。

## 第二轮：生成中心入口收敛计划

**状态：S1～S5 已实现并完成离线与浏览器隔离验收（2026-11-20）。**

本轮承接第一轮任务流程与可信依据，不重做任务引擎。目标是让生成中心围绕“输入主题 → 查看生成过程 → 按大纲继续生成”组织，减少重复入口。

### 1. 页面与交互契约

生成中心从上到下保留四块：

1. **新建学习主题**：主题输入框、主要按钮“开始生成”、次要按钮“先存起来”；附次级入口“从已有笔记生成”。
2. **生成任务**：复用 GenerationTasks 的节点、可信依据、停止/继续/删除及学习入口。当前进行中的任务优先展示；历史记录可收起。
3. **领域大纲**：复用 OutlinePanel，查看路线、逐课生成和进入已有课程。
4. **待学清单**：默认折叠，显示待处理数量；展开后可搜索、开始生成、移出清单，并查看条目来源。

原三个模块的去向：

| 原模块 | 新位置 | 保留的能力 |
| --- | --- | --- |
| 想学的 | 底部折叠“待学清单” | 暂存主题、以后启动生成 |
| 刚冒出的 | 阅读器内“延伸问题” | 查看问题出处、加入待学清单、忽略 |
| 能学的 | 顶部“从已有笔记生成”选择弹窗 | 搜索并选择已有笔记用于备课 |

状态规则：

- “先存起来”仅保存条目，不创建后台任务、不调用模型、不写知识库。保存成功后清空输入；失败保留输入并显示错误。
- “开始生成”沿用主题调研与首门样课机制；请求成功后定位并展开对应任务，请求失败保留输入。重复点击不得启动重复活跃任务。
- 待学条目成功启动任务后标记已发起，从默认待处理列表移出；任务失败/停止后在任务区继续，不把任务状态复制成第二套可操作状态。
- 待学清单提供“已发起”筛选及关联任务入口；移出清单不停止或删除任务。
- 任务删除不自动重新启动生成，也不把关联清单条目标记为待处理；条目仍可手动再次加入待处理。已形成的大纲及发布课程保留。
- 删除/移出清单不修改 Obsidian 原文；以后扫描同一来源不能立即把用户隐藏的条目重新加回。
- 标题相同不等于同一门课；不同笔记路径独立可选，不凭名称猜测课程归属或覆盖关系。

### 2. 已核实的实现缺口

- `Catalog.todo` 混合 Obsidian 待探项与已发起调研的历史任务，不是独立待办存储，不能直接承担“先存起来”。
- `confirm_spark` 当前只记录确认，`build_catalog` 未把确认的问题加入待学清单；需要补齐明确的持久关联。
- Spark 候选目前来自 Tutor 检索轨迹；触发搜索可能只是核实，不能将其标为“课件有缺漏”或自动立项。
- Trace 有课程及执行标识，但 Spark 响应目前仅暴露问题、key、page_id 等信息；迁往阅读器前需补充可靠出处。
- 旧待探项按标题触发任务；新清单需要稳定 ID，任务发起后保存关联，避免把标题当作条目身份。
- 页面中能学的笔记只代表“有材料”，不代表材料足够或事实已核实；保留现有生成与发布门禁，不提前展示合格承诺。

### 3. 数据与接口原则

- 待学条目单独存入 SQLite，与任务执行记录分离；新增表只增不删，可回退到原页面，不改写学习记录或知识库。
- 条目至少包含：稳定 ID、主题、规范化去重键、待处理/已发起/已移出状态、创建时间，以及可选任务关联（kind、target、action_id）。任务最新状态由现有任务服务提供。
- 来源单独保留类型与稳定来源标识：手动输入、Obsidian 待探项、学习延伸问题；同一主题来自多处时保留全部出处，不丢失原始标题、笔记相对路径或课程引用。
- 同一来源重复导入、同一按钮重复提交保持幂等；主题仅作保守规范化去重，不用模型模糊合并不同学习需求。
- 旧待探项和明确确认的 Spark 按来源幂等接入；未确认候选不自动加入。已发起的历史任务继续只在任务区展示，不批量变成新的待办。
- 延伸问题关联优先使用 Trace 的 course_id、run_id 及原有 page_id（当前项目兼容字段）；无可靠课程归属的历史问题放在待学清单内的次级“待归类问题”抽屉，不猜测挂课、不丢弃。
- 忽略和移出均保存处理记录；不直接修改或删除 Trace 原文。
- 增加待学清单的列表、保存、移出/恢复、发起任务接口；发起过程复用现有任务幂等与绑定能力，保存失败不得伪报启动成功。
- 增加按课程查询延伸问题及处理的接口；“加入待学”需要一次操作同时完成清单保存和来源确认，避免半成功。
- 笔记选择优先复用现有 catalog 的只读笔记数据；已有发布/失败/处理中状态改为明确动作：查看课程、查看任务或继续任务，不能只因“曾请求”永久禁用。
- HTTP 请求和响应由后端 Pydantic 定义，重新生成 OpenAPI TS；不另写跨端共享类型。

### 4. 实施任务与验收

| 编号 | 用户可观察的交付 | 主要改动范围 | 依赖与验收 |
| --- | --- | --- | --- |
| S1 | 输入主题后可“先存起来”，刷新后仍在；旧待探条目可见 | catalog schema、待学存储/service/router、隔离测试、生成类型 | 无前置；验证新增/空白校验/重复保存/移出后不反弹/旧来源幂等接入；保存不启动任务 |

| S3 | 生成中心只常驻新建、任务、大纲与折叠清单；笔记通过弹窗选择 | StudioPage、待学清单组件、笔记选择组件、公共出口 | 依赖 S1/S2；输入与提交错误态完整；已发起不占默认待办；弹窗支持搜索/空态/错误/键盘操作；复用现有任务与证据面板 |

### 5. 验证矩阵与完成条件

- **后端隔离测试**：使用临时 SQLite、模拟 Trace/笔记/子进程，覆盖保存与启动分离、来源去重、软移出、任务启动失败、重复请求、候选归属、旧确认接入以及任务删除后的关联展示。
- **契约检查**：生成 API TS，类型和真实响应一致；不修改 Agent 循环、工具清单或提示词。
- **前端检查**：相关 lint、TypeScript、生产构建；已有用户修改单独保留，不借改造全站重构。
- **浏览器隔离验收**：新主题立即生成/暂存、待办再启动、笔记选择、阅读器问题加入/忽略、无出处兜底、空态/失败态、刷新持久化、390px 与桌面布局、键盘焦点与弹窗恢复。
- **既有回归**：逐课点单、停止/继续/删除、可信依据失效、课程阅读、复习、批改和笔记确认入口保持可用；本轮不触发真实模型、真实批改或知识库写入。
- **最终交付**：生成中心不再展示原三个独立区块；旧条目与旧候选均有可解释去向；“保存”“启动任务”“形成大纲”“发布课程”状态可区分，不靠标题或模型推断状态。

### 6. 范围外

本轮不增加 Agent、不自动判断候选是否值得开课、不生成可信度分数、不增加推荐算法、不重做课程库或任务引擎、不自动合并或删改已有大纲，不新增依赖。真实模型端到端生成仍作为独立验收，不与页面改造混跑。

### 第二轮实施与验收记录（2026-11-20）
